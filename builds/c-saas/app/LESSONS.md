# Lessons from past builds — apply these

## L001 — Verify Stripe webhook signatures before trusting events
**Problem:** Unverified webhooks let attackers forge subscription state.

**Fix:** In stripe_webhooks, check the Stripe-Signature header against STRIPE_WEBHOOK_SECRET before mutating subscription_status.

## L003 — JWTs need short TTL + revocation at scale
**Problem:** Long-lived stateless JWTs can't be revoked, a liability as user count grows.

**Fix:** Keep access tokens short-lived, issue refresh tokens, and maintain a revocation list once past MVP.

## L004 — Panel-upgrade logic must surface the load-management third path (NEC 625.42 EVEMS)
**Problem:** Binary panel assessment (fine or upgrade) misses the ~1k EVEMS alternative that saves homeowners 2-4k and makes otherwise-rejected installs viable. No competitor surfaces this at intake.

**Fix:** Three-way routing: fine / load-management candidate / upgrade likely. Apply in scoring, estimator, and operator logic.

## L005 — Sample test data must be generated by the actual code, not hand-crafted
**Problem:** Hand-crafted lead test data drifted from the estimator JS output — stored estimates did not match what the code computes from the same inputs, giving false confidence in integration.

**Fix:** Generate test data by calling the real computation, or validate hand-written data against the code on every run.

## L006 — Scoring models that only reward risk signals bury the best leads
**Problem:** A scoring function that adds points only for problems (panel risk, deadline urgency) and commitment but never for readiness (complete info, easy install) makes the best leads indistinguishable from uncertain ones.

**Fix:** Add readiness points for completeness (all fields present, no gaps) and favorable signals (adequate panel, short run). A dream lead should score highest.

## L007 — Windows PYTHONUTF8=1 required for yard tools
**Problem:** assemble.py fails with UnicodeEncodeError on Windows cp1252 when writing files containing Unicode characters. The yard tools assume UTF-8 but Python on Windows defaults to cp1252.

**Fix:** Set PYTHONUTF8=1 before running yard tools on Windows, or open files with explicit encoding=utf-8.

## L008 — Generated model routes need get_db wired to the real session factory
**Problem:** gen_models.py generates routes with a placeholder get_db() that raises NotImplementedError. FastAPI Depends captures the function at import time so monkey-patching the module attribute after import does not work.

**Fix:** Replace the placeholder in the generated routes.py with a direct import from scrapyard.database.db_session before any route uses Depends(get_db).

## L009 — Stored file paths must be normalized to forward slashes for cross-platform portability
**Problem:** catalog.json stored paths with os.path.relpath which returns backslashes on Windows. build_matrix passed 5/5 on Windows but on Linux the backslash is a literal filename character so assemble fails on all templates. The gate was green but the artifact was OS-locked.

**Fix:** Normalize to forward slashes at the source (index_catalog.py: .replace(os.sep, '/')). Make consumers tolerant of either separator (.replace('/', os.sep)). Regenerate the catalog after fixing.

## L010 — A green backend gate is not proof for anything a human touches - the gate must render and judge the UI
**Problem:** build_matrix checked backend routes returning 200 but never rendered the frontend. Every app shipped a raw JSON 404 as its UI while the gate reported PASS.

**Fix:** Add verify_frontend.py: boot app, headless Chrome screenshot, judge against frontend-standard.md rubric. A stub frontend FAILS the gate.

## L011 — Frontend parts marked core were stubs that passed because nothing looked at them
**Problem:** scrapyard/frontend parts (dashboards, forms, tables) rendered unstyled HTML fragments. gen_frontend_react.py produced a login stub. All marked core status. All passed build_matrix because the gate never rendered.

**Fix:** Rebuild generate_runtime_app.py to emit Jinja2+Tailwind templates (base, dashboard, error). Every assembled app serves a designed page at / by default. React stays opt-in.

## L012 — A passing structural gate still requires human eyes on the rendered screen
**Problem:** Frontend gate 19/19 PASS but the screenshot showed duplicate seed data, escape-char leaks in drafts, and em-dashes that read like AI. Structural DOM analysis cannot catch content, voice, or data-quality bugs.

**Fix:** Gate is necessary but not sufficient. Every rendered screen must be signed off by a human. Add voice.md punctuation rules (plain dashes, no curly quotes). Validate demo data after rendering.

## L013 — Scoring must reward readiness not just risk - the best lead should score highest
**Problem:** A scoring function that only awards points for problems makes the best leads indistinguishable from uncertain ones. A committed buyer with a clean panel scored the same as one with an unknown panel.

**Fix:** Add readiness points: panel-fine, right-sized amps, complete info, contactable. Rebalance so dream leads reach HOT and hard leads reach HOT-flagged. Shoppers cap at WARM.

## L014 — User-typed special characters must be tested through the real input path not seed data
**Problem:** A dollar-sign corruption was dismissed as seed-script-only. The real input path was clean but the dismissal delayed proving it. Every text bug must be verified through the real POST-store-render cycle with the problematic characters.

**Fix:** Test the real API input path with special characters (dollar, quotes, ampersands, angle brackets) and verify the rendered output before declaring fixed.

## L015 — Text corruption from escaped characters is one bug class regardless of the character
**Problem:** Em-dash leaks, newline leaks, and dollar-sign corruption are the same class: text written through one encoding and read through another without roundtrip validation.

**Fix:** Any text a human reads must be tested through the full write-store-render cycle with special characters before calling it done. Structural gate checks do not catch encoding bugs.

## L016 — TestClient is not a real browser - core flows must be proven through a real DOM
**Problem:** TestClient bypasses JS, DOM events, and fetch. A broken onclick or failed fetch passes TestClient but fails in a real browser.

**Fix:** Add a Selenium e2e suite that drives a headless browser against a live server. Each core interaction exercised through the real DOM.

## L017 — SMTP log transport is not proof of email delivery
**Problem:** Log transport prints to console but never exercises the real SMTP code path. Auth failures and encoding bugs are invisible.

**Fix:** Start a local SMTP catcher, point the app at it, send a real email, capture and verify the message.

## L018 — WSL2 Docker is unreliable for sustained test runs - verify infra stability first
**Problem:** Docker containers in WSL2 stopped 3 times during testing. App worked when they were up but the full journey could not complete end to end.

**Fix:** Verify containers stay up for 10+ minutes before committing to a Docker-based test plan. If unstable, use native Docker Desktop or a cloud VM.

## L019 — WSL2 port forwarding is broken - run Docker tests from inside WSL
**Problem:** WSL2 NAT does not reliably forward container ports to Windows. Hours wasted debugging container crash loops that were actually port forwarding failures.

**Fix:** Run test scripts from inside WSL where container ports are locally reachable. This is a WSL2 networking limitation.

## L020 — The factory measured software-sellable but not marketable
**Problem:** Build scored 9+ on impl but had no landing page, pitch, pricing, or competitive positioning. Phase 1 research fed product decisions but not marketing copy.

**Fix:** Add marketing-standard.md and verify_marketing.py. Landing page must lead with outcome, trace claims to research, name the buyer and differentiator, and contain no fabricated social proof.

## L021 — Marketing gate checks source keywords not source truth - fabricated citations need human verification
**Problem:** The gate detected 'FractalEV' and 'Source:' in the copy but cannot verify the citation is real. Derived numbers were presented as cited facts and a Google Ads CPC was misattributed to Angi.

**Fix:** Every cited number must be manually traced to its source. The gate is necessary but not sufficient. Add a checklist item requiring human citation verification.
